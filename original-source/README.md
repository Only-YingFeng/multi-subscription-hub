# Clash 节点备份助手 1.0.2

这是带中文界面的便携 Windows EXE。电脑需要安装并运行 Clash Verge Rev，浏览器需要 ZeroOmega。软件自带所需运行环境，不需要另外安装 Python 或 Node.js。

界面按已选深色样板重建为原生 Qt 窗口，默认 1200 × 850。首页在一屏内显示节点表、输出目录、生成文件、写回及回滚；节点列表内部滚动，高级路径在单独窗口中设置。最小化、最大化和关闭位于深色标题区。

上方“探测环境”和“生成备份”是有边框和悬停提示的小按钮，完成后持续显示绿色高亮与勾选；第三步仅显示进度。写回使用右侧下方的大按钮：写回前保持紫蓝渐变，尚未具备前提时悬停提示先探测和生成，待写回时点击并确认后执行；已校验生效时显示绿色“已写回并生效”，不再接受重复点击。

## 使用流程

1. 在 **Clash Verge Rev 中更新或切换订阅**，等待节点载入，并选择规则模式。
2. 打开 `ClashZeroOmega.exe`，点击 **探测环境**。软件核验本机环境后逐条测试指定节点；等待检测完成，查看节点表中的连通性结果。
3. 探测成功后，选择输出目录，点击 **生成备份**。如果新订阅的代理组同时包含直连、拦截或代理选项，软件会要求明确选择这些组在浏览器中的分流动作。
4. 若右侧显示 **待写回**，点击 **写回 Clash 扩展配置**。软件先私有备份，再将本地 SOCKS5 入口及分流脚本写入当前订阅关联的持久扩展配置，热重载 Mihomo，并校验生效状态。确认窗口会说明可能短暂中断连接。若显示 **已写回并生效**，可直接跳过。
5. 在各浏览器 ZeroOmega 设置中，用 **从备份文件恢复** 导入生成的 `ZeroOmega-全节点-手动选择-Mihomo分流.bak`，再从右上角菜单选择具体节点。

**订阅下载和更新由 Clash 完成。** 本软件读取 Clash 当前已载入的节点；“写回 Clash 扩展配置”会保存和启用本机入口脚本，不向机场拉取订阅。更新节点后重复上述流程即可。`.bak` 供 ZeroOmega 恢复使用，不写入 Clash。

## 连通性与写回状态

节点表的 **连通性** 显示“可用 · 耗时 / 超时 / 测试失败 / 未测试 / 已失效”。软件调用 Mihomo 的指定真实节点接口，向一个固定 HTTPS 204 测试地址发小流量请求；并发最多 4 条，每条测试上限约 6 秒。结果是本次测试目标在检测当时的快照，不代表所有网站都可访问。核心启用统一延迟时可能内部发送两次请求；软件保留该设置。

检测不会选择默认节点、切换代理组或重载核心，只会更新 Mihomo 的延迟测试历史。失败节点仍保留在完整备份中；浏览器选中失败节点时不会自动改选其他节点。再次点击探测即可重新测试。

右侧 **Clash 回写状态** 单独说明本工具的持久扩展和本地入口是否生效。节点连通性通过不代表扩展已经写回；扩展已经生效也不保证远端节点始终可用。

## 行为与边界

- 每个真实节点对应一个完整名称的 ZeroOmega 情景模式，地址为 `127.0.0.1` 的 SOCKS5 端口。浏览器可以同时选择不同线路。
- Mihomo 保留原配置的直连、拦截与规则顺序；代理请求绑定所选节点，未命中规则的请求使用该节点代理。节点异常不会自动选择其他线路。
- 电脑主路由、原代理组选择、系统代理、TUN、DNS 保留。生成仅写入本工具的备份、状态和导出文件；写回及回滚单独确认并热重载核心。
- 旧端口保留，不按节点排序重排，也不回收给其他订阅。退役节点仍保留同名情景与端口，入口拒绝请求。不要删除私有状态目录，否则不能安全承接原映射。
- 新订阅使用独立节点身份。完整原名尽量保留；重名或不符合 ZeroOmega 命名要求时才加最少的区分文字。
- 没有原生模板时使用内置 schemaVersion 2 格式。高级设置可选择纯本地 SOCKS5 原生 `.bak` 模板；不接受包含凭据、PAC 或自动切换规则的模板。
- 不读取浏览器登录数据库，不修改运行中的扩展存储。恢复 `.bak` 会使用 ZeroOmega 自己的恢复操作，请先备份你要保留的现有插件选项。
- 默认私有状态目录为当前用户本地应用数据中的 `CodexClashZeroOmega`，仅当前用户与 SYSTEM 可访问。旧工具用户可在高级设置选择原私有状态目录。
- “回滚本工具”移除本工具管理的入口及扩展并保留端口登记；存在外部改动时停止，避免覆盖。它不撤销在 ZeroOmega 中手动恢复的备份。

## 当前兼容范围

已验证 **Clash Verge Rev 2.5.7、Mihomo 1.19.32、ZeroOmega 3.5.2 原生备份格式**。仅支持内嵌节点、内嵌规则和已核验的订阅扩展形式；provider、正则、自定义子规则或复杂订阅扩展会停止并提示。其他版本需重新核验后支持，不应忽略版本检查。

Windows x64；本次在 Windows 11 上验证。未在朋友的电脑、其他 Windows 版本或其他 Clash 版本上验收。

## 分享与开发

可分享发布包中的 EXE、本说明和第三方许可，也可直接分享发布 ZIP。发布包不含本机 `.bak`、节点表、订阅、私有备份或用户状态。每位用户使用自己的 Clash 配置生成。

发布 ZIP 的 `源码` 目录保留本应用的可重建源文件与原始图标，`第三方许可` 包含 Qt、Python、Node 及图标库说明。可以修改或替换 Qt 依赖后重新构建；程序没有修改 Qt 或 PySide 的库源码。具体许可与对应依赖源码链接见 `第三方许可/UI/NOTICE.md`。

源码环境为 Python 3.13、Node.js 25.2.1。进入发布包的 `源码` 目录，在独立环境安装 `requirements-build.txt` 后构建：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements-build.txt
.\.venv\Scripts\python.exe -B .\build.py --node "本机 Node.js 25.2.1 的 node.exe 路径" --output "发布目录"
```

无界面环境诊断与生成也可用于排查（这两个命令不做远端连通性测试，不回写或重载核心）：

```powershell
.\ClashZeroOmega.exe --detect-json .\探测结果.json
.\ClashZeroOmega.exe --generate --output .\导出 --result-json .\生成结果.json
```

含分流冲突时请使用界面确认后生成。更新与回滚日常通过界面操作，原有 CMD 工具仍保留在原目录。

图标由内置 Image Gen 根据已选设计制作；生成原图保留在源码，提示词保留在项目设计产物中。EXE 嵌入多尺寸 ICO，窗口及任务栏使用同一标识。按钮与状态图标使用 QtAwesome 授权图标字体。
